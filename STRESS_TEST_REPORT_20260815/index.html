    Trinity 压力测试报告（2026-08-15 优化后复测）

    一、测试配置

    轮次 写入 读取 混合 线程 规模
    A 2000 2000 1000 16 高并发大负载
    B 500 500 250 8 中并发对照

    工具：scripts/full_stress_test.py（引擎层，不依赖 HTTP） 环境：Windows / Python 3.14 / MemoryAggregator 内存池

    二、结果（优化后）

    轮次 A（2000/2000/1000/16线程）

    阶段 QPS p50 p99 错误
    写入 30,342 13.18ms 51.99ms 0
    检索(hybrid) 956 32.37ms 38.53ms 0
    混合 22,925 28.53ms — 0
    资源 内存 202.5MB / CPU 59.3%
    一致性 池 1128 / agents 32 / 锁错误 0

    轮次 B（500/500/250/8线程）

    阶段 QPS p50 p99 错误
    写入 12,230 5.43ms 42.6ms 0
    检索(hybrid) 200 6.18ms 2474ms* 0
    混合 21,901 7.33ms — 0
    资源 内存 198MB / CPU 37.5%
    一致性 池 336 / agents 16 / 锁错误 0

    * 检索 p99 偶发 2.4s——为冷启动/ANN 首次竞争（非稳定尾部，A 轮同指标仅 38ms）

    三、优化前后对比（同配置 800/800/400/12线程）

    指标 优化前 优化后 提升
    写入 QPS 166 18,479 111x
    写入 p50 2032ms 8.27ms 246x
    混合 QPS 112 23,401 209x
    检索 p50 12ms 12ms 稳定
    锁错误 0 0 稳定

    四、结论

    1. 写入吞吐：12k-30k QPS（规模越大越高），p50 5-13ms——从"2 秒级"到"毫秒级"， 压测优化（sklearn + 预热 + 非阻塞）完全生效。
    2. 检索：p50 6-32ms 稳定，p99 偶发冷启动波动（非稳定尾）——高并发下反而更稳 （16 线程 p99=38ms）。
    3. 混合读写：21k-23k QPS，无锁冲突——并发正确性优秀。
    4. 资源：198-202MB 内存 / 37-59% CPU——大负载下仍轻量。
    5. 零错误：三轮（A/B + 此前）全部 errors=0、锁错误=0。

    五、剩余优化点

    • 检索 p99 偶发尾部（冷启动/ANN 首次竞争）：建议 ANN 索引启动预热 + 检索路径 提前建索引，可进一步收敛尾部延迟（已列入后续）。
    • 内存 200MB：池内记忆+向量索引+多通道对象，大池场景可考虑索引压缩。
