# Trinity 运维结论备忘（2026-08-15，round34-36）

## 1. 双通道检索语义（勿混淆）

| 通道 | 默认行为 | 全库检索 |
|---|---|---|
| 原生 `trinity_search`（DSH 插件） | 按当前会话身份隔离（agent_id=dsh-<sessionId>，F4 设计）——新会话无自有记忆时返回空 | 显式传 `agent_id="default"`（或指定 agent） |
| `mcp__trinity__memory_search` | 全局（无身份注入） | 默认即全库 |

如需统一：调用方按需求显式传 `agent_id`/`persona_id`；不改变默认（隔离是安全特性）。

## 3. collector 零事件结论（非故障）

- `BackgroundScanner` 监听 6 个内置 agent 缓存目录（`active_collection.listen_agents`），
  当前部署无兼容 agent 运行时向缓存写事件 → events_captured=0 属"无源"。
- 若要启用采集：需 agent 运行时（AgentConnector 目标）接入，或配置自定义事件源。

## 4. 安全/隔离（round35 修复）

- 🔴 修复：hybrid 检索的 agent/persona/tenant 过滤此前**完全失效**（`get_memory_owners`
  未实现 → post-filter 死代码）。现已实现（SQLite/PG），过滤真实生效。
- 语义缓存 key 已含隔离 scope，跨租户不串缓存。
- 建议生产启用 `TRINITY_API_KEY`；`auto_redact_pii` 写入开关。

## 5. 每日维护链（autostart 03:00）

`mirror → decay → tiers → consolidate → dedup → sync`
（mirror 对齐维护 PG；decay/tiers 治理大库；consolidate 睡眠式整合；dedup 实体去重；sync 双端同步）
