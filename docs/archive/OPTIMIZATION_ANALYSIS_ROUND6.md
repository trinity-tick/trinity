# Trinity 第六轮优化空间分析（2026-08-24：数据质量实证 + 生产案例对照）

> 方法：前五轮覆盖能力面/机制面/实证面/模型能力面/资产面。本轮转向
> **最后一公里**——①本地**真实数据质量深挖**（首次实测检索面纯度）；
> ②网络**生产级记忆集成案例与踩坑**（3874 记忆膨胀、证据置信度、UMP/OMP）。
> 结论：发现一个 P0 数据问题（文档噪声污染检索面）+ 两个 P1 方向。

## 一、本地实证：真实数据质量（首次量化）

### 1.1 检索面纯度问题（🔴 P0，本轮最重要发现）

**实测**：active 集 1,889 条中 **462 条（24%）是 doc:* 类**（doc:general 151 /
doc:summary 95 / doc:plan 42 / doc:benchmark 42 / doc:ops 34 / doc:protocol 18）——
文档 dump（[PREAMBLE] 元数据、复盘表格、markdown 大段）混入交互记忆检索面。

**检索污染量化**：
- `Raft` 查询 top-10 中 **7/10（70%）是 doc:summary**；
- `数据库端口 5430` 命中 Decision 而非直接答案、`Raft 共识` 命中"其他亮点"——
  精确事实查询被文档噪声干扰；
- 13% active 含 markdown 表格、36% 含标题（文档特征）。

### 1.2 数据卫生（✅ 良好）
- **精确重复 0 组**（去重治理有效）；
- 极短/测试残留 ~1.3%（11 条极短 + 13 条压测/自动关联）——少量可清理；
- 检索相关性整体良好（8/10 查询命中相关）。

### 1.3 网络互证（生产案例调研）
- **《After 3,874 Memories…Couldn't Find Anything Useful》**（dev.to）：记忆膨胀
  到数千条后召回失效、信噪比归零——**Trinity 的 24% 文档噪声正是同类问题的
  早期形态**（1,889 条中 24% 是噪声，继续膨胀将复现 3874 案例）；
- "检索噪声淹没信号"是记忆系统失效模式共识之一（无淘汰/去重/证据校验的系统
  净收益可转负）。

## 二、网络新视角 → Trinity 差距

### 2.1 记忆/知识分层（🔴 与本地实证同一问题）
- 共识：**RAG 静态知识 vs 记忆交互事实应分层**（Mem0 官方立场；文件式 vs
  外挂记忆两派中，"文件式保真 + 语义召回"成主流——编码 agent 用 AGENTS.md/
  CLAUDE.md 存权威事实，向量库仅做检索加速）；
- Trinity 现状：doc:* 与交互记忆同库同检索面——**违背分层共识**，且文档
  dump 无结构化（原始 markdown 大段），召回质量差。

### 2.2 证据与置信度（🟡 P1，era/mnemos 方向）
- 2026 实践：每条记忆带**来源 + 时间戳 + 证据计数**；召回时弱证据/过期
  记忆**降权或标注"需复核"**（ERA: Evidence-based Reliability Alignment）；
- Trinity 现状：审计链可查来源（✅ 基础好），但**检索端无证据强度/置信度
  标注**——聚合池有 confidence 字段但引擎库无；无法区分"检索到了"与
  "确定是对的"。

### 2.3 淘汰策略显式化（🟡 P1）
- 生产共识：按 **token 预算 + 条目数分层（热/温/冷）**，超限淘汰低证据项，
  "agent 需要的不是更大窗口而是淘汰策略"；
- Trinity 现状：有 decay/tiers（多因子 + LLM 摘要）✅，但**无"检索面 token
  预算"分层**（热/温/冷）——文档类占检索面正是无预算分层的体现。

### 2.4 协议层新动态（🟢 观察）
- **UMP（Universal Memory Protocol）** vs **OMP（Open Memory Protocol）**：
  记忆成为"MCP 工具 + A2A 协调"之外的第三互操作层——2026 下半年标准化竞赛；
- Trinity：AGENTS.md 导出（R7）+ markdown 全集导出（R7 第 60 轮 P1-④）已
  对齐"可移植/反锁定"方向 ✅；待 UMP/OMP 定稿后可评估对接。

## 三、优化建议（按 ROI）

### P0（高价值，1-2 天）
| # | 优化 | 依据 | 动作 |
|---|---|---|---|
| 1 | **记忆/知识分层（doc 类分离）** | 本地实测 24% 文档噪声 + Raft 70% 污染 + 3874 案例 + 分层共识 | 检索端默认排除 doc:*（或单独 `include_docs` 参数）；doc 类走独立知识检索面（对应 R7"不做文档解析层"的折中——不解析，只隔离） |
| 2 | **检索面 token 预算分层（热/温/冷）** | 淘汰策略共识 + 文档占面实证 | 给 doc:* 设检索面上限（如 active 检索面 doc 占比 ≤10%）；超限走归档 |

### P1（中等价值，各 1-2 天）
| # | 优化 | 依据 | 动作 |
|---|---|---|---|
| 3 | **证据/置信度标注** | ERA/mnemos 方向 + Trinity 审计链基础 | 检索结果附带 `evidence`（来源/版本/审计）与 `confidence`（弱证据降权或标注"需复核"） |
| 4 | **噪声清理脚本** | 本地实测 1.3% 残留 + doc dump | slim 类脚本：清理极短/测试残留；doc:general 大段标记 |

### 🟢 观察（不动作）
- UMP/OMP 协议：待标准化定稿后评估对接（AGENTS.md/markdown 导出已对齐方向）；
- 文件式记忆：已实现（AGENTS.md + 全集导出），无需新增。

## 四、收敛判断

**第六轮结论：优化空间聚焦为"检索面纯度"——这是六轮以来首次通过本地
数据实测（而非网络对比）发现的实质问题**：

1. **P0 两项**（doc 分层隔离 + 检索面预算）直接对应生产案例的 3874 记忆
   膨胀教训——在 Trinity 1,889 条（24% 噪声）阶段治理，避免重蹈覆辙；
2. **P1 两项**（证据置信度 + 噪声清理）对齐 2026 可信记忆方向，审计链
   基础已具备；
3. **已确认无差距**：检索质量（去重 0 重复）、成本、安全、评测口径、
   协议方向（文件式对齐）。

**一句话：六轮对比后，剩余优化已收敛到"数据纯度治理"——doc 分层隔离 +
检索面预算 + 证据标注，做完后 Trinity 的检索面将完全符合 2026"记忆与
知识分层、有证据、有淘汰"的生产共识。**
