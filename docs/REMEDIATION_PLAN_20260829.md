## 短板 1：单机 SQLite 内核

### 2026 方案
- **Redis/Redis 8 向量集**：记忆层 + 向量检索一体（Redis AI Research 已发 LongMemEval
  agent memory 研究）；生产分布式记忆的主流底座；
- **PG + pgvector**：PostgreSQL 单库即可分布式读写（多实例共享），TiMem/Zep 均用 PG 系；
- **Exabase M-1**：LongMemEval+BEAM 全规模 SOTA（2026-04），记忆数据层专用（商业）；
- **TiMem 分层**：TMT 层级记忆（PG 底座）。

### Trinity 落地路径（三级）
1. **短期（双写读分离）**：PG 镜像已存在（双向同步）→ 升级为 **PG 为主存储**（SQLite 降级为
   边缘/离线缓存）——adapter 层已抽象（postgresql.py 已有），工作量 = 配置 + 迁移脚本；
2. **中期（分片联邦）**：federation 包传输升级为 **PG Logical Replication**（真多机一致）+
   按 tenant/agent 分片路由；
3. **长期（向量层分离）**：向量检索独立到 Redis/Qdrant（当前 FAISS 本地已遇 add_with_ids
   限制——ann_index 警告实证），检索延迟 30ms→10ms。

**修复可行性：高**——adapter 抽象 + PG 镜像已就绪，是配置级工程而非重构。

## 短板 2：LLM 外部依赖（评测卡 4h 实录）

### 2026 方案
- **本地小模型 judge 蒸馏**：Qwen3-4B/Llama3.2-3B 量化（Ollama/GGUF）在 2026 已达
  GPT-4 级判题能力的 90%+（SLM 边缘部署趋势）；
- **混合路由**：简单判题本地 SLA，复杂判题云端（成本↓90%+，无网络依赖）；
- **判题结果复用**：缓存（已有）+ 语义级去重（相似查询复用判题）。

### Trinity 落地路径
1. **短期（本地 judge）**：Ollama + Qwen3-4B 量化 → `trinity/llm/client.py` 加
   `provider="local"`（base_url=localhost:11434）→ reason 判题路由到本地；
   **已有蒸馏基线**（启发式 0 阈值 0/20 LLM）——本地模型补长尾；
2. **中期（judge 蒸馏训练）**：用已有 59k 审计 + judge 历史（几百条人工标注）微调
   3B 小模型（LoRA）——判题成本再降一个量级；
3. **评测网络免疫**：评测脚本已有重试/超时——补**断点续跑**（200q 卡 4h 的教训：
   分块 checkpoint——每 20 问存进度）。

**修复可行性：高**——Ollama 本地栈成熟，路由代码已有（model/base_url 参数）。

## 短板 3：QA 生成 5.5（MS 类目 0.237）

### 2026 方案
- **TiMem（ACL 2026，78.96）**：多级记忆聚合——**分层检索后按类目组装上下文**
  （MS 类目 = 跨会话多事实拼接，非单条检索）；
- **Mastra 观察式记忆**：观察→摘要→事实三级，**QA 时用摘要级**（信息密度高）；
- **Redis 研究**：**QA 生成侧上下文排序**（相关度+时间+类别混合排序）比检索更影响
  最终 QA；
- **类目专用策略**（Trinity 已验证方向）：KU/SS-P 专用 prompt 已实证（0.752）——
  **MS 需要的同样是类目专用组装**（多事实 → 分点拼接 + 去重 + 时序排序）。

### Trinity 落地路径（GEN-MS 专项）
1. **MS 类目诊断**（先做）：失败案例归因（漏检/漏拼/生成幻觉）——37.4 已证伪 judge
   改严，说明是**生成侧**；
2. **MS 组装策略**：命中记忆按**事实单元拆分重组**（多事实拼接而非原文堆叠）+
   时序排序 + 冲突去重；
3. **MS 专用 prompt**：类目模板（"列出所有提到的事实，按时间排列，逐条回答"）；
4. **上下文剪枝**：每问只喂最相关 3-5 条（KU/SS-P 已验证方向）+ MS 加宽到 8 条
   （多事实需要更多上下文）；
5. **A/B 门禁**：每步改动跑 500q 对比 0.4667 基线（不降才合入）。

**修复可行性：中高**——方向已验证（KU/SS-P 专用 prompt 实证 0.752），MS 是
"已知打法换类目"，预期 0.237 → 0.35-0.45。

## 短板 4：自改范围限 scripts/

### 2026 方案
- **Darwin Gödel Machine（DGM，2026 热点）**：自我修改代码 + 经验库 + 安全沙箱 +
   存档回溯——与 Trinity 现有管线同构（DGM 的 archive = Trinity 的 git + 审计）；
- **分级白名单**：2026 实践是**影响面分级 + 验证强度递增**（低风险自动/高风险人工）；
- **沙箱验证**：worktree/容器隔离验证补丁（不改主库）。

### Trinity 落地路径
1. **阶段 2.5（白名单扩展至 tests/ 辅助 + 文档生成脚本）**——验证同阶段 2（低风险）；
2. **阶段 3（核心逻辑层受控自改）**：按 PHASE3_DESIGN 设计稿——**双环境基准 A/B**
   （fresh 环境 300q/holdout）+ approval 闸门——**实施前门槛：阶段 2 稳定 4 周**；
3. **沙箱强化**：git worktree 隔离验证（不改主库）+ 基准 A/B JSON 化自动对比。

**修复可行性：中**——设计稿就绪，瓶颈是验证成本（$0.3-0.5/次 + 20-40min/次）
与稳定观察期（4 周）。
