## 四、结论

1. **写入吞吐**：12k-30k QPS（规模越大越高），p50 5-13ms——从"2 秒级"到"毫秒级"，
   压测优化（sklearn + 预热 + 非阻塞）完全生效。
2. **检索**：p50 6-32ms 稳定，p99 偶发冷启动波动（非稳定尾）——高并发下反而更稳
   （16 线程 p99=38ms）。
3. **混合读写**：21k-23k QPS，无锁冲突——并发正确性优秀。
4. **资源**：198-202MB 内存 / 37-59% CPU——大负载下仍轻量。
5. **零错误**：三轮（A/B + 此前）全部 errors=0、锁错误=0。

## 五、剩余优化点

- **检索 p99 偶发尾部**（冷启动/ANN 首次竞争）：建议 ANN 索引启动预热 + 检索路径
  提前建索引，可进一步收敛尾部延迟（已列入后续）。
- **内存 200MB**：池内记忆+向量索引+多通道对象，大池场景可考虑索引压缩。
